[第 5 讲]({{< relref "/notes/cs168-distance-vector" >}})记的是“怎样学到路”，今天补上“**旧路失效后，怎样发现、通知，以及避免互相误导**”。课程重点和今天的疑问放在一起回看。

## 1. 两个计时器：多久说一次，多久不听就作废？

| 机制 | 记住什么 |
| --- | --- |
| Advertisement interval | 周期通告的发送间隔，通常整张表共用一个发送计时器 |
| 路由条目 TTL | 每条动态路由各自的有效期，收到当前下一跳对该目的地的有效更新后续期 |
| Triggered update | 表项改变时尽快通告，不必等下一个周期；用来加快收敛 |

这里的 **TTL 是路由表项的寿命，不是 IP 包头中逐跳递减的 TTL**。

周期发送用来弥补丢包、持续确认路由；条目过期表示“这条路太久没被确认”，**不证明整个邻居一定宕机**。本地若直接检测到链路 down，就可处理受影响路由，不必等 TTL。

RIP 的参照值是约 **30 秒更新、180 秒超时**，不是所有 DV 的统一常数；留出多个周期，是为了容忍偶发丢包。失效路由可先标成不可达、停止转发，再暂留通告给邻居，之后清理。[RFC 2453：计时器](https://www.rfc-editor.org/rfc/rfc2453.html#section-3.8)

## 2. Poison、Split Horizon、Poison Reverse 别混成一件事

固定目的地 D，假设 **A 当前经 B 到 D**：

| 机制 | A 做什么 | 想解决什么 |
| --- | --- | --- |
| 过期毒化，Rule 5 | 路由失效时，通告到 D 的成本为 ∞ | 主动传播坏消息，别让别人继续信旧路 |
| Split Horizon，Rule 6A | 向 B 发通告时，省略这条路由 | 别把依赖 B 的路线推荐回 B |
| Poison Reverse，Rule 6B | 向 B 发通告时，把这条路由报成 ∞ | 明确告诉 B：“别经我走，我这条路依赖你” |

**区别在于：Rule 5 是路真的失效了；Rule 6B 是针对当前下一跳的通告策略。** A 仍可通过 B 正常到 D，也仍能向其他邻居通告真实成本。

今天问“为什么还要加 Poison Reverse”，要记住：在课件模型中，**6A 与 6B 是两种替代选择**。对同一个下一跳、同一条路由，不能既不发送，又发送 ∞。6B 的显式否定，也能更快打断已经出现的两节点互相依赖。

## 3. Count-to-Infinity：旧消息为什么能“续命”？

先看一个**没有启用 6A/6B**的手推例子，链路成本均为 1；不是运行实验：

```text
A —— B —— D（目的地）
```

| 事件 | A 到 D | B 到 D |
| --- | --- | --- |
| 正常时 | 2，经 B | 1，直达 |
| B–D 断开，A 尚未收到坏消息 | 仍认为 2，经 B | ∞ |
| B 听到 A 的旧报价 2 | 2，经 B | **3，经 A** |
| A 听到当前下一跳 B 报 3 | **4，经 B** | 3，经 A |
| 再互相通告 | 4、6、8…… | 5、7、9…… |

B 以为 A 提供了另一条路，但 **A 的路本来就经过 B**，于是形成 `A → B → A`。Rule 2 又要求接纳当前下一跳的变差更新，成本就不断上涨。

**TTL 未必能救场：双方还在不断通告、互相刷新条目。** 两节点互骗可用 6A 或 6B 阻止；更长的依赖环仍可能发生，但不是“只要拓扑里有三角形就一定出环”。[RFC 2453：Split Horizon 与环路](https://www.rfc-editor.org/rfc/rfc2453.html#section-3.4.3)

课程的 **Rule 7** 给计数设上限：按 RIP 的约定，成本达到 **16 就视为 ∞**，有限可达范围为 1–15 跳。它让错误计数最终停下，**不保证暂态环路从未出现**。

## 4. 七条规则，一张回看表

课件把第 6 条列为 A/B 两种选项，所以表中有八行：

| 规则 | 记忆句 |
| --- | --- |
| 1 · Bellman–Ford | 候选成本要加链路成本，更优就换 |
| 2 · Next-Hop Updates | 当前下一跳的更新要接，包括变差和 ∞ |
| 3 · Resending | 定期重发，弥补丢失的通告 |
| 4 · Expiring | 条目长期未获确认，就失效 |
| 5 · Poison Expired Routes | 失效不要只沉默，向邻居通告 ∞ |
| 6A · Split Horizon | 不把依赖下一跳的路报回给它 |
| 6B · Poison Reverse | 或者报回去，但对它报 ∞ |
| 7 · Count to Infinity | 设置有限的 ∞，给上涨的成本封顶 |

发送时机也分清：**表变化时、周期到时、条目过期时**。链路新增/断开也可导致表变化；触发更新加快信息传播，但不是消除所有环路的保证。[官方课件](https://docs.google.com/presentation/d/1bwx7O8ZLDfFKeZzOrqcUg_X8F13j6SM62DHJ8gEk7ho/edit)第 111–113 页可对照。

## 回看时，先问自己这四句

1. 这是发送计时器，还是某条路由的过期计时器？
2. 这个 ∞ 来自真实失效，还是只对下一跳使用 Poison Reverse？
3. 邻居说的“另一条路”，会不会其实依赖我？
4. 双方还在互相更新，TTL 为什么不一定到期？

**规则本身不复杂，难的是异步、丢包、旧消息和故障交错时，局部看似合理的选择仍可能组成全局环路。** 以后手推题就盯住“谁依赖谁”，比背术语更有用。
