学完这节课，我还在问“信号量就是更高级的锁吗？”用**可用许可的数量**来理解：成功的 `sem_wait()` 消耗一个许可，没有就等；`sem_post()` 提供一个许可，暂时没人等时也能留给之后的线程。

## 1. 初值就是一开始允许通过几次

| 初值 | 用途 | 例子 |
| --- | --- | --- |
| `0` | 等事件 | 父线程等子线程完成某一步。子线程先 post，父线程后来也能通过 wait |
| `1` | 互斥 | 进入临界区前取许可，离开时归还。用作锁时要配对，避免多 post |
| `N` | 限制数量 | 有 N 个空位，可以先发放 N 个写入许可 |

记住与上节[条件变量](../cs537-queue/)的差别：**条件变量的通知不累计，信号量的许可可以累计。** 信号量没有 mutex 的持有者约束，可以由另一个线程 post，正好用来做事件同步。

**课件里的 −1 从哪来？** 在教材的抽象记账法里，初值 1，A 取走后变 0，B 再 wait 就记为 −1，表示有一个等待者。A post，计数回到 0，B 获得许可。Linux 的 `sem_getvalue()` 在有等待者时报告 0，不能用负数判断排队人数。读实现时记住“锁保护计数，计数为 0 就在条件变量上等待，醒后重查，再减 1”即可。 [OSTEP §31.1、§31.8](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-sema.pdf) · [Linux sem_getvalue](https://man7.org/linux/man-pages/man3/sem_getvalue.3.html)

## 2. 有界队列：先拿空位或数据，再拿互斥锁

队列初始为空且容量为 N，设 `empty = N`、`full = 0`，另用一把 mutex 保护数组和读写下标。“生产者可以先跑 N 次”只表示**如果消费者还没取走数据，前 N 次取空位不会因队列满而阻塞**。生产者第一次放入数据并 post 后，消费者就有机会继续。

| 步骤 | 生产者 | 消费者 |
| --- | --- | --- |
| 取得许可 | `sem_wait(&empty)` | `sem_wait(&full)` |
| 拿锁后操作队列 | 写入并推进写下标 | 取出并推进读下标 |
| 解锁后发布许可 | `sem_post(&full)` | `sem_post(&empty)` |

这是教材的多生产者、多消费者方案，表格用于手推，未运行实验。单槽例子靠两个许可让读写交替。扩到多槽、多生产者后，**拿到了空位许可，不等于选中了唯一的数组下标**，两名生产者可能写同一格。局部变量 `i` 各自独立，选槽和更新的队列状态却是共享的。 [OSTEP §31.4](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-sema.pdf)

**顺序为什么不能反？** 队列满时，生产者若拿着 mutex 等 `empty`，消费者就拿不到 mutex 来腾空位。普通 `sem_wait()` 不会帮忙释放外面的 mutex。回想条件变量，`pthread_cond_wait()` 接收 mutex，等待时会释放它，返回前再获取。

## 3. 哲学家就餐：互斥成立，还要看能不能推进

- **死锁怎么出现**：每人先拿一根筷子，再等邻居手里的另一根，形成循环等待。
- **统一编号怎么解**：每个人先拿编号小的，再拿大的。等待链沿编号递增，无法绕回起点。这个规则排除了该循环，单个哲学家能否最终吃到还取决于调度和公平性。 [OSTEP §31.6](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-sema.pdf)
- **状态方案怎么读**：在同一把锁下检查两侧邻居。自己 `HUNGRY` 且邻居都没在吃，就先标记自己为 `EATING`，再 post 自己的信号量。放下筷子时复查左右邻居。相邻者不能同时得到许可，符合条件的非相邻者可以并行进餐。无死锁与无饥饿需要分别判断。

回看时先问自己三个问题：**计数代表什么？哪一步会阻塞？谁能提供下一份许可？**
